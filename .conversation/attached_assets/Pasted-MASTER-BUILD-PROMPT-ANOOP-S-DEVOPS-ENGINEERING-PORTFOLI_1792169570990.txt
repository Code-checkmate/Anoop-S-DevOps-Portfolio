1. Your role and primary objective

Act as a senior frontend engineer, UI/UX designer, and QA engineer.

Build a complete, polished, responsive, multi-page personal portfolio website for Anoop S., a DevOps professional.

This must be a functioning website, not merely a design mockup, a single landing page, or a static screenshot.

The portfolio should communicate practical DevOps experience, Linux operations, cloud technologies, application deployment, CI/CD, automation, professional training, and hands-on projects.

The site must have a distinctive engineering identity. Its individual pages should take visual inspiration from familiar developer and DevOps products while retaining original branding, original copy, and a consistent overall design system.

2. About
3. Skills
4. Projects

Implement all nine pages and their navigation before considering the work complete.

2. Technology stack and implementation requirements

Use the following stack unless the existing Replit environment makes a specific choice incompatible:

- React
- TypeScript
- Vite
- React Router for client-side routing
- CSS or CSS modules for styling, with shared design tokens
- Lucide React for icons, if successfully installed
- Local TypeScript data objects for page content

Use stable, mutually compatible dependency versions.

Before making changes, inspect the existing project files and package configuration. Preserve useful existing configuration when possible. Do not unnecessarily replace working project infrastructure.

If starting from an empty project, initialize the application correctly.

Engineering rules

- Use reusable React components.
- Use TypeScript types for reusable data structures.
- Keep page content and project data separate from presentation components.
- Avoid one enormous component containing the entire application.
- Avoid unnecessary libraries, complicated build plugins, experimental APIs, and brittle CSS.
- Do not use browser APIs during server-side rendering or module initialization.
- Do not introduce a backend that requires unprovided credentials.
- Do not expose secrets, API keys, tokens, or credentials.
- Use semantic HTML and accessible form controls.
- Implement meaningful loading, empty, error, and success states where applicable.
- Use stable keys when rendering lists.
- Ensure every internal navigation link points to a real route.
- Ensure buttons either perform their stated action or are clearly presented as unavailable until configured.
- Do not leave broken links, dead buttons, unfinished routes, or console errors.

If a preferred optional dependency cannot be installed, use a simple native alternative rather than abandoning the build.
